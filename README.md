# 舞台走位校验系统

一款舞台走位（Blocking）校验 Web 应用：在「舞台区域连接图」上标注各区域间的通行耗时、**通道容量**与**通道封闭时段**，为演员按时间下达「到位口令」（可带**停留时长**），系统从上一口令时刻出发**逐边推演**相邻口令之间的实际行进过程——进入连接若与封闭时段重叠，会在区域**原地等待**或**自动改走其他路径**，据此计算**最早到达时刻**并标出**无法按时抵达**的区段；两种走位模式算出逐边路线后，还会汇总所有演员对同一无向连接的**占用区间**做**通道占用冲突**校验，支持编辑后即时重算与一键导出 Markdown 校验报告。还可在当前校验模式下保存**走位方案基线快照**，编辑后即时对照基线列出新增 / 移除区段及状态、迟到、路线、通道冲突的变化。新增**应急疏散快照**：输入事件时刻并选择出口区域，按当前校验模式的实际路线还原每位演员当时的位置并计算最早疏散路线，页面按最晚撤离优先展示，报告追加同一快照。新增**跨演员口令依赖**：可在两条口令间维护「前置完成后至少等待 N 秒才可执行后置」的有向约束，保存前对整张依赖图做环检测（成环拒绝写入并提示闭环口令链），校验时按当前模式的实际时刻逐条判定满足 / 违约 / 无法判定，页面即时重算、删除口令级联清理，报告追加依赖汇总与明细。新增**演员换装核查**：为同一演员相邻两条到位口令（一个区段）登记换装区域与所需整数秒数（每个区段最多一项），按当前校验模式取得该区段实际出发时刻，依次计算「起点 → 换装区」与「换装完成 → 终点」两段最早路线（两段均计入通道封闭造成的等待或绕行，非静态最短耗时直接相加），页面展示换装完成时刻、最终到达时刻、相对下一口令的余量与准时 / 迟到 / 不可达状态，切换模式或修改区域连接后即时重算，仅评估该区段、不改写原走位结果，删除关联口令或区域时任务自动清理。新增**排练数据 CSV 导入**：下载模板后批量导入排练口令，按「姓名 + 角色」复用演员、按区域名解析目标，上传即逐行预览时间 / 停留格式、未知或重名区域、文件内重复与现有口令冲突，错误行禁止提交；预览生成带数据版本的导入计划，提交时底库已变化返回 409 要求重新预览，否则一次性原子写入全部新演员和口令，成功后刷新校验结果并展示新增数量。新增**现场走位复盘**：上传 UTF-8 CSV（`演员姓名,角色,实际时刻,实际区域`）后仅解析现有演员与区域，未知或歧义值逐行报错；服务端按演员将实际记录与计划口令做保持先后顺序的一对一最优对齐（配对时差绝对值、区域不符加 300、漏执行口令 / 多余记录各加 180，同成本再按配对数、实际记录行号字典序决胜），页面展示每位演员的配对、时间 / 区域偏差及漏项 / 多项汇总，并可下载本次复盘 Markdown；上传分析为只读操作，不改写任何走位数据。新增**观众视线遮挡检查**：以整数厘米维护观众点（x、y、眼高）、舞台目标（x、y、目标高）与轴对齐矩形遮挡物（x、y、宽、深、高），服务端对每条「观众 → 目标」视线段用 slab 法分数运算**精确裁剪**其与各矩形投影的相交参数区间（边界接触算相交、视线高度等于遮挡物高度算被挡，不只测矩形中心或采样点），按最小进入参数确定首挡物，并给出使视线严格越过全部相交遮挡物的最小整数目标高度与建议抬高量；页面用 SVG 绘制平面关系图（点击视线与表格行可互相定位），表格列出首挡物、相交区间与建议抬高量，数据随底库持久化。新增**舞台吊挂布景载荷核算**：维护同一横梁上的吊点（横坐标、额定载荷）与吊挂件（重量、重心横坐标、左右吊点、生效起止秒数），仅允许重心位于两吊点之间；按**力矩平衡**计算每件对两吊点的分担重量，以**有理数（分数）累计和比较**，累计载荷恰好等于额定载荷不判超额、避免临界值舍入误判；按半开时段 `[起, 止)` 汇总各吊点载荷（**同秒结束先于开始**），输出每个吊点的**峰值载荷、超额区间及超额量**并**合并相邻连续超额区间**；删除被引用的吊点时提示并拒绝，数据随底库持久化。

内置两种校验模式，可在结果区一键切换：
- **连续口令延误传导**（默认）：首条口令视为准时到位，之后逐段连续推演——实际出发时刻取「计划时刻与实际到达时刻的较晚值」再加停留时长，**某段迟到会传导给后续区段**，后续间隔充足时可**吸收延误、恢复准时**；
- **区段独立校验**：每段均从上一口令计划时刻出发，段与段互不影响（即旧版行为）。

技术栈：Node.js + Express + 原生 HTML/CSS/JavaScript（无任何前端构建步骤）。

## 变动说明（连接编辑提交边界修复）

`PUT /api/edges/:id` 过去在**端点重复检查之前**就把新端点 / 耗时 / 容量 / 封闭时段写入了内存中的现存记录，重复检查命中而返回 409 时，脏状态已经留在内存里：随后的 `GET /api/data` 与 `GET /api/validate`（走位校验）会读到被串改的连接，而**下一次任意成功保存**还会把这份脏状态整体写入数据文件。

现已收紧提交边界（HTTP API、页面编辑流程与 Compose 启动方式均不变）：

- **按拟更新后的完整连接判重**：先用请求体构造「更新后字段」再判重，检查通过前不改动任何现存记录；
- **正反方向视为同一对**：无向连接 `(A,B)` 与 `(B,A)` 是同一对端点，与除自身外的任一条现存连接同对即返回 **409**；
- **冲突时零副作用**：409 时被编辑连接（含端点、耗时、容量、封闭时段）及其它数据的**内存状态与数据文件都保持原样**，错误文案仍为「两个区域之间已存在连接」；
- **合法编辑一次生效**：检查通过后一次 `Object.assign` + 单次落盘，走位校验随即按新连接（含新耗时 / 容量 / 封闭时段）重算。

调用示例（以下 ID 取自内置示例数据）：

```bash
# 合法编辑：改耗时 / 容量 / 封闭时段（端点不变）→ 200，随后走位校验按新连接重算
curl -X PUT http://localhost:3000/api/edges/edge-wingr-center \
  -H 'Content-Type: application/json' \
  -d '{"a":"area-wing-r","b":"area-center","seconds":7,"capacity":3,"closures":[{"start":20,"end":25}]}'

# 非法编辑：端点改成另一条现存连接（edge-wingl-center = 侧台左↔舞台中央）→ 409
# 同时夹带的 seconds/capacity/closures 修改不会生效，内存与数据文件均保持原样
curl -i -X PUT http://localhost:3000/api/edges/edge-wingr-center \
  -H 'Content-Type: application/json' \
  -d '{"a":"area-wing-l","b":"area-center","seconds":99,"capacity":9,"closures":[{"start":1,"end":2}]}'
# HTTP/1.1 409 Conflict
# {"error":"两个区域之间已存在连接"}

# 反方向同样视为同一对端点，结果完全一致
curl -i -X PUT http://localhost:3000/api/edges/edge-wingr-center \
  -H 'Content-Type: application/json' \
  -d '{"a":"area-center","b":"area-wing-l","seconds":99,"capacity":9,"closures":[]}'
```

回归测试见 `test/edge-update.test.js`（`npm test`，使用独立临时数据目录，不影响 `data/`）。

## 变动说明（吊挂载荷大分数叠加显示修复）

「吊挂布景载荷核算」在多件分数分担叠加时会出现显示失真：同一左吊点连接约 140 个间距各异（质数厘米）的右吊点、每件 1 kg、重心距右吊点 1 cm 且同时生效时，左吊点累计载荷为 140 个 `1/p` 之和，约分后的分子 / 分母长达 300 余位。此时**精确分数仍能计算**（峰值、超额判定均正确），但 `kg` 字段由 `Number(分子) / Number(分母)` 计算——两个数百位的整数转成浮点数都是 `Infinity`，`Infinity / Infinity = NaN`，JSON 序列化后 `kg` 变为 `null`，页面两位小数显示为 `NaN`。

现已把两位小数的生成改为**全程 BigInt 精确舍入**（HTTP API、页面展示结构与 Compose 启动方式均不变）：

- **服务端**：`kg = round(分子/分母 × 100) / 100` 改用 BigInt 整除完成（`round(x) = floor(x + 1/2)`，半数进位），**绝不先把巨大分子 / 分母转成浮点数再相除**；舍入后的商仅为「载荷 × 100」量级，转数值无精度问题。`/api/rigging` 响应仍为 `{ num, den, kg }`：`num` / `den` 为精确分子分母字符串，`kg` 恒为有限的两位小数数值；
- **页面**：峰值、超额区间峰值、超额量与逐件分担的两位小数直接取服务端精确舍入的 `kg`，「两位小数是否除尽」的判断改用 BigInt 取余，展示格式不变（如 `2.17…（=精确分数）`）；
- **顺带修正**：恰好落在 `.xx5` 边界的分数（如 `136296/4800 = 28.395`）旧浮点路径因二进制表示误差会少进 0.01（显示 `28.39`），现按精确分数半数进位为 `28.40`，且 `kg` 字段与页面显示始终一致；
- **行为不变**：半开时段 `[起, 止)`（同秒结束先于开始）、严格超额判定（超额 = 载荷严格大于额定载荷，恰好等于额定载荷不报超额）、相邻连续超额区间合并均仍按分数精确执行，数据刷新后显示有限数值与正确状态。

复现与回归测试见 `test/rigging-large-fraction.test.js`（`npm test`，使用独立临时数据目录，不影响 `data/`）：140 个质数间距吊挂件叠加场景下，逐一校验全部 `kg` 为有限数值、`num`/`den` 与独立 BigInt 核算一致、超额区间与逐件分担精确，并覆盖半开接续不叠加、恰好等于额定不超额与 `.xx5` 边界舍入。

## CSV 引号规则（导入与复盘共用同一个解析器）

「排练数据 CSV 导入」与「现场走位复盘」上传的 UTF-8 CSV（可带 BOM，支持 CRLF / LF 换行）由同一个严格解析器处理。引号按其在字段中的位置区分三种状态，**任何非法引号都判定为文件结构错误**，导入预览 / 提交与复盘分析 / 报告**一律直接拒绝（HTTP 400）、不继续解析任何一行**，不会把含错内容当作有效姓名或数据：

- **字段起始**：一个字段尚未写入任何字符时，只有在该位置遇到 `"` 才允许开启「引号字段」；字段一旦先写过普通字符（包括空格），其后再出现 `"` 即为非法。
  - ❌ 错误：`张"三"丰`（未加引号的字段中间出现引号；旧解析会吞掉引号把 `张三丰` 当有效姓名，现已直接拒绝）；
  - ❌ 错误：`  "张三"`（引号前有空格，该字段视为未加引号，引号非法）；
  - ✅ 正确：姓名本身含引号时，从字段开头整体加引号并转义内部引号——`"张""三""丰"` 表示姓名 `张"三"丰`。
- **引号内**：引号字段中的逗号、换行都按普通字段内容保留（不会被当成列分隔或行分隔）；要表示一个**字面双引号**，必须写成**两个连续双引号 `""`**（如 `"a""b"` 表示 `a"b`）。
- **闭合引号之后**：结束引号后只允许紧跟逗号（下一字段）、换行（下一行）或文件结束；其后再出现任何字符（含空格、文字、另一个引号）均为非法。
  - ❌ 错误：`"张三"丰`、`"张三" "`、`"张三" ,…`（闭合引号后夹带字符）。
- **引号必须成对**：文件结束时仍有引号字段未闭合，按结构错误拒绝，错误信息给出引号字段的起始物理行号。

合法用法不受影响，完整保留：普通逗号分隔、CRLF / LF 换行、引号字段内的逗号与换行、以及 `""` 双引号转义。判断依据是文件原文结构，与是否能匹配到底库演员 / 区域无关——结构非法时不会产出任何预览行或对齐结果。

## 一键启动（Docker Compose）

前置条件：已安装 Docker（含 Compose 插件）。在项目根目录执行：

```bash
docker compose up --build
```

启动成功后，容器内服务监听端口 **3000**，Compose 默认将其映射到主机 **3000** 端口：

| 访问对象 | 地址 | 端口 |
| --- | --- | --- |
| **Web 页面**（浏览器直接打开） | http://localhost:3000 | 3000 |
| **REST API 基址**（接口均挂在 `/api` 下） | http://localhost:3000/api | 3000 |
| API 健康/数据示例 | http://localhost:3000/api/data | 3000 |

即 Web 与 API 同端口（`3000`），API 路径统一以 `/api` 开头（接口清单见下文「API 概览」）。如主机 3000 端口被占用，可修改 `docker-compose.yml` 中 `ports` 的左侧主机端口（如 `"8080:3000"`），容器内端口与各接口路径不变。后台运行可加 `-d`，停止用 `docker compose down`。

> 首次启动时，若数据文件不存在，系统会自动写入内置示例数据（9 个舞台区域、11 条连接——其中 2 条带封闭时段、1 条容量为 2、3 位演员、12 条口令、3 条跨演员口令依赖，含刻意设计的「等待」「绕行」「超时」「不可达」「停留导致迟到 → 延误传导 → 间隔吸收恢复准时」、两位演员并发占用「通道占用冲突」以及依赖在不同模式下「满足 / 违约 / 无法判定」的演示区段；另有 5 项换装任务，演示「准时（含通道封闭等待）」「余量随校验模式变化」「换装后迟到」与「换装区域不可达」等换装核查情形；另有 4 个观众点、2 个舞台目标、5 个遮挡物，演示「通视」「等高边界接触被挡」「相交但未遮挡」「最小整数目标高度建议」与「眼高不高于遮挡物且起点在其投影内 → 无法抬高解决」等视线情形；另有 7 个吊点、9 件吊挂件，演示「正常不超额」「单段分数超额（超额量 575/3 kg）」「同秒结束先于开始 + 相邻连续超额合并为 [00:00, 01:00)」与「三件各分担 1/3、累计恰好等于额定载荷不判超额」等吊挂载荷情形）。

## 配置项

| 环境变量 | 默认值 | 说明 |
| --- | --- | --- |
| `PORT` | `3000` | Web 服务监听端口（Compose 中映射为主机 3000 端口） |
| `DATA_DIR` | `./data`（容器内 `/app/data`） | 数据文件 `data.json` 存放目录 |

Compose 默认将数据目录挂载为命名卷 `stage-data` 以持久化修改；执行 `docker compose down -v` 删除卷后重启即可恢复示例数据（也可在页面右上角点击「恢复示例数据」）。

## 功能说明

- **舞台区域**：维护区域名称与备注（如 舞台中央、侧台右、后台化妆间）。
- **区域连接**：维护无向连接、通行耗时（秒）、**通道容量**（同一时刻允许并发占用的人数，1～10，缺省 1）与**通道封闭时段**（可添加多段起止秒数区间），同一对区域仅允许一条连接。
- **演员**：维护演员姓名与角色。
- **排练数据 CSV 导入**：在「📥 排练数据 CSV 导入」卡片下载 CSV 模板、批量上传排练口令：
  - **演员复用 / 新建**：按「**姓名 + 角色**」匹配现有演员——唯一匹配则复用，无匹配则自动新建，同名且同角色不唯一时该行报错（不猜测是哪一位）；
  - **区域解析**：按区域名精确匹配，**未知区域 / 重名区域**均为错误行（导入不会新建区域）；
  - **逐行校验**：时间支持 `90`（秒）或 `01:30`（分:秒），停留秒数为 0～600 的整数（留空按 0）；文件内重复按**解析后的「演员身份 + 目标区域 + 整数秒」**判定——同一演员、同一区域的 `90` 与 `01:30` 会被解析为同一时刻，预览标出**文件内首次行**（标注「文件内首次出现」，非错误）与其后的**重复行**（错误行）；同时标出**现有口令冲突**（复用演员已有同时刻同区域口令，同样跨时间格式判定）；演员身份 / 区域 / 时间无法解析的行只保留原格式错误，不混入重复判断；
  - **模板与预览**：模板为带表头的 UTF-8 CSV（Excel 直接打开不乱码），上传后不写库、只展示逐行预览与新增演员 / 口令数量；**存在错误行时提交按钮禁用**；
  - **乐观并发**：预览计划带**数据版本**（底库区域 / 演员 / 口令的哈希）；提交时若底库已被修改（任何标签页的增删改），服务端返回 **409** 并要求重新预览，重新预览后再提交；
  - **原子写入**：提交时服务端按原始 CSV 重新解析校验，并**复用预览的同一判重口径**（演员身份 + 区域 + 解析后整数秒）复核文件内重复与现有口令冲突，命中即**整批拒绝、不写任何演员或口令**（不会产生空演员或部分口令、也不会静默跳过）；通过后一次性写入全部新演员与口令并单次落盘，任何落盘失败均回滚；合法文件的**预览新增数与实际新增数一致**，成功后自动刷新数据与校验结果并提示新增数量。
- **现场走位复盘**：在「🎬 现场走位复盘」卡片上传 UTF-8 CSV（表头固定为 `演员姓名,角色,实际时刻,实际区域`，时刻支持秒数或 `mm:ss`）：
  - **仅解析现有值**：演员按「**姓名 + 角色**」、区域按**名称**精确解析；未知演员 / 区域、同名同角色演员或重名区域造成的**歧义**、时刻格式错误均**逐行报错**，错误行不参与对齐（不会自动新建任何数据）；
  - **保序一对一最优对齐**：服务端按演员分组，计划侧按「计划时刻 / 口令 ID」、实际侧按「实际时刻 / CSV 行号」排序，用序列对齐 DP 求保持两侧先后顺序的一对一最优对齐，**同一实际记录不重复匹配**；
  - **成本口径**：配对成本 = `|实际时刻 − 计划时刻|`（时差绝对值），计划区域与实际区域**不符加 300**；每条**漏执行口令**或**多余实际记录**各加 **180**；总成本相同时**先取配对数多者**，再取**实际记录行号序列字典序较小者**；
  - **结果展示**：逐演员列出配对（计划口令 ↔ CSV 行号、实际时刻 / 区域、时间偏差早到 / 晚到秒数、区域偏差与配对成本）以及**漏执行口令 / 多余实际记录**汇总，顶部给出总行数、错误行、配对数、漏项 / 多项、区域不符、时差合计与总成本徽章；
  - **Markdown 下载**：点击「下载本次复盘 Markdown」由服务端按原始 CSV 重新计算后下载与页面同口径的复盘报告（汇总、CSV 逐行解析问题、每位演员的配对 / 漏项 / 多项明细）；
  - **只读分析**：上传与下载均**不改写走位数据**（不新增 / 修改 / 删除任何演员、区域或口令），可安全重复上传。
- **到位口令**：按「演员 + 目标区域 + 时间」下达口令，时间支持 `90`（秒）或 `01:30`（分:秒）两种输入格式；每条口令可设 **0～600 秒停留时长**（缺省 0，用于连续口令延误传导模式）。
- **校验结果**：对每位演员，将其口令按时间升序排列，逐边推演（时间依赖 Dijkstra）：
  - ✅ **按时**：最早到达时刻 ≤ 下一口令时刻，显示余量秒数、最早到达时刻与实际路线；
  - ❌ **超时**：最早到达时刻 > 下一口令时刻，红色高亮并显示「所需 X 秒 / 可用 Y 秒、缺口 Z 秒」；
  - ⛔ **不可达**：两区域在连接图上不连通（封闭时段只会造成等待或绕行，不会造成不可达）。
  - 🚶 **通道占用冲突**：结果区顶部汇总全部冲突事件，发生冲突的区段在路线旁逐条标记关联冲突。
- **延误传导展示**：连续口令延误传导模式下，结果区逐段列出**计划/实际出发时刻、实际到达、继承延误与最终迟到**，演员标题处给出传导链末端状态（最终迟到或「延误已全部吸收」）。
- **走位方案基线对比**：在当前校验模式下可将一次校验结果**保存为基线快照**；此后编辑区域、连接、演员或口令，结果区会**即时对比当前结果与基线**（无需手动刷新）：
  - 以「**演员 ID + 相邻口令 ID**」组成稳定区段键匹配，新增 / 删除 / 重排口令都不会按数组位置错配；结果区分组列出**新增区段**与**移除区段**；
  - **共有区段**逐项对比：按时 / 超时 / 不可达**状态**、**实际到达时刻**、**迟到秒数**、**实际路线**与**关联通道冲突**（冲突按「连接 + 超载时段」匹配，不依赖冲突序号）；
  - 顶部汇总徽章给出**状态转好 / 转差**、**迟到增减**、**通道冲突新增 / 解除**的区段计数；无差异时提示「与基线完全一致」；
  - 基线按校验模式分别保存：切换到另一种校验模式时，若该模式没有基线而另一模式存在，会**提示模式不一致且不做比较**（可一键清除另一模式的基线）；
  - 支持**覆盖**基线（用当前结果重新保存）与**清除**基线；基线随数据文件**持久化**（保存在数据文件的 `baselines` 字段中，恢复示例数据时一并清空）；
  - **导出的 Markdown 报告会追加同样的对比摘要**（基线信息、总体变化、汇总计数对比、新增 / 移除区段表与共有区段变化明细表）；当前模式没有基线时报告不包含该章节。
- **应急疏散快照**：在「应急疏散快照」卡片输入事件时刻并勾选一个或多个出口区域，系统按当前校验模式的实际路线还原每位演员当时的位置并计算最早疏散路线：
  - **位置还原**：逐边时间轴精确到秒——🚶 **通道行进中**（含所在通道、方向与剩余秒数）、⏱ **区域等待**（通道封闭等待 / 等待下一口令时刻）、🧍 **停留**（计划停留 / 走位结束后停留）；
  - **疏散计算**：位于通道者**先按原方向走完剩余路程**，再从到达区域按事件时刻之后的封闭时段（等待或绕行）计算到任一出口的最早路线；位于区域者从事件时刻直接计算；已位于出口区域者耗时为 0；
  - **位置未知**：因不可达链（区段不连通）或事件时刻早于走位时间轴而无法确定位置时，单独标为位置未知，**不做猜测**；
  - **结果展示**：按**最晚撤离优先**排序（无法疏散视为最晚），列出位置、出口、到达时刻、耗时与疏散路线；数据编辑或切换校验模式后快照随动重算；
  - **报告联动**：快照生成后，「导出校验报告」的 Markdown 会在文末追加同一快照。
- **跨演员口令依赖**：在「🔗 跨演员口令依赖」卡片选择前置 / 后置口令（可属于不同演员）并填写至少等待秒数，维护「前置口令完成后至少等待 N 秒，后置口令才可实际出发」的有向约束：
  - **成环拒绝**：每次新增保存前检查整张依赖图（含自环），**成环时返回 400 并在错误信息中给出闭环口令链（演员 + 时刻 + 区域），本次不写入**；同一对口令的同方向重复依赖返回 409；
  - **逐条判定**：校验时以**前置口令在当前模式下的实际到达时刻 + 其停留时长**作为完成时刻，与**后置口令的实际出发时刻**（前往该口令区段的实际出发时刻）比较，列出 ✅ **满足**（余量秒数）、❌ **违约**（缺口秒数）与 ❓ **无法判定**（前置 / 后任一端不可达、后置是其首条口令无实际出发等）；
  - **即时重算**：新增 / 删除依赖或编辑任何走位数据、切换校验模式后立即重新评估，结果区分违约 / 未知 / 满足排序展示；
  - **级联清理**：删除口令（含删除演员 / 区域连带删除口令）时自动删除与该口令相关的全部依赖；
  - **报告联动**：「导出校验报告」的 Markdown 追加「跨演员口令依赖」汇总徽章与明细表（前置完成、后置实际出发、相差秒数与结论）。
- **演员换装核查**：在「👔 演员换装核查」卡片为同一演员**相邻两条到位口令**（一个区段）登记换装任务——选择相邻口令区段、换装区域并填写所需整数秒数（0～3600），**每个区段最多一项**（重复登记返回 409）：
  - **两段动态推演**：按**当前校验模式**取得该区段的实际出发时刻（传导模式含停留与继承延误），先算「起点 → 换装区」的最早到达，加上换装秒数得**换装完成时刻**，再自该时刻算「换装区 → 终点」的最早到达；两段均计入通道封闭造成的**等待或绕行**（时间依赖 Dijkstra），不是静态最短耗时的直接相加；
  - **结果展示**：逐项列出实际出发、到达换装区、换装完成、最终到达四个时刻、相对下一口令的**余量 / 缺口**与 ✅ 准时 / ❌ 迟到 / ⛔ 不可达 / ❓ 无法评估状态，并给出两段逐边路线（含等待标注）；
  - **仅评估不改写**：换装核查只评估该区段，不回写、也不影响原走位校验结果（与通道占用冲突、基线对比无关），不参与 Markdown 报告；
  - **即时重算与级联清理**：登记 / 删除任务、编辑区域连接或口令、切换校验模式后立即重算；删除关联口令或区域（含删除演员连带删口令）时任务自动清理，数据随底库持久化。
- **等待展示**：结果区在路线下方逐边列出出发 / 到达时刻，并以 ⏱ 徽标标出**等待位置（区域）与时长**。
- **观众视线遮挡检查**：在「👁 观众视线遮挡检查」卡片查看自动生成的逐对分析（每位观众点 × 每个舞台目标）：
  - **精确相交区间**：服务端对每条视线段与各轴对齐矩形遮挡物的投影做 slab 法分数裁剪，给出精确的相交参数区间 `[进入 t, 退出 t]`（边界接触、角点相切都算相交；不是只测矩形中心或采样点）；
  - **遮挡判定**：相交区间内视线高度 ≤ 遮挡物高度即被挡（**等于也算被挡**）；按**最小进入参数**确定首挡物；
  - **建议抬高**：给出使视线**严格越过全部相交遮挡物**的最小整数目标高度与建议抬高量；若观众眼高不高于某相交遮挡物且视线起点位于其投影内，则明确标注「无法通过抬高目标解决」；
  - **SVG 平面图**：按平面坐标（y 轴向上）绘制遮挡物矩形（红框为某视线的首挡物）、观众点、舞台目标与逐对视线（绿 = 通视、红 = 被挡、黄虚线 = 无法抬高解决），点击视线或表格行可互相定位；
  - **即时重算与持久化**：观众点 / 舞台目标 / 遮挡物的增删改保存后立即重新分析，数据随底库 JSON 文件持久化。
- **吊挂布景载荷核算**：在「🏗 吊挂布景载荷核算」卡片维护同一横梁上的**吊点**（横坐标、额定载荷）与**吊挂件**（重量、重心横坐标、左右吊点、生效起止秒数）：
  - **力矩平衡分担**：每件按「左点分担 = 重量 ×（右点横坐标 − 重心横坐标）÷ 吊点间距、右点分担 = 重量 ×（重心横坐标 − 左点横坐标）÷ 吊点间距」分担到两吊点，两件分担之和恒等于重量；
  - **有理数精确核算**：分担量与逐吊点累计载荷全程以分数（BigInt 分子 / 分母）运算和比较，累计载荷**恰好等于额定载荷不判超额**（超额 = 严格大于），避免临界值舍入误判；
  - **半开时段汇总**：吊挂件按 `[起, 止)` 生效，**同秒结束先于开始**（t 秒结束与 t 秒开始不叠加）；逐吊点输出**峰值载荷**、**超额区间**（载荷 > 额定载荷）与**超额量**，首尾相接的连续超额自动**合并为一条区间**；
  - **删除保护**：删除被吊挂件引用的吊点返回 409 并提示引用它的吊挂件；修改吊点横坐标若使某吊挂件重心不再位于两吊点之间（或左右吊点横坐标关系被破坏）返回 400 并拒绝写入；
  - **即时重算与持久化**：吊点 / 吊挂件的增删改保存后立即重新核算，数据随底库 JSON 文件持久化。
- **即时重算**：任何新增 / 编辑 / 删除操作（含封闭时段、停留时长编辑）保存后立即重新校验并刷新结果。
- **导出报告**：点击「导出校验报告」下载 Markdown 格式报告，与当前校验模式一致（含汇总表、**通道占用冲突汇总与明细**、**跨演员口令依赖汇总与明细**、每位演员的区段明细、**逐边动态路线明细**，传导模式下另附**延误传导明细**）。
- **级联一致性**：删除区域会同时删除相关连接与口令；删除演员会同时删除其全部口令；删除口令（或因删除区域 / 演员连带删除口令）会同时删除相关的跨演员口令依赖；删除口令或区域（含连带删除口令）会同时删除相关的演员换装任务。

## 排练数据 CSV 导入操作说明

1. 在「📥 排练数据 CSV 导入」卡片点击「**下载 CSV 模板**」，得到含 `姓名,角色,目标区域,时间,停留秒数,口令说明` 表头的 UTF-8 CSV（模板内附两行示例，正式导入前请删除或替换）。
2. 逐行填写排练口令：`姓名` + `角色` 用于匹配演员（角色可留空）；`目标区域` 必须与底库区域名**完全一致**；`时间` 填秒数（如 `90`）或 `mm:ss`（如 `01:30`）；`停留秒数` 留空按 0；`口令说明` 可留空。字段中如需逗号或换行可**从字段开头**用双引号整体包裹，字段内的 `"` 一律写成两个 `""`（详见上文「CSV 引号规则」）；未加引号的字段中出现引号（如 `张"三"丰`）或闭合引号后仍有字符属于**文件结构错误**，预览与提交都会整体拒绝（不会把错误内容当成姓名新建演员），请修正后重新上传。
3. 点击「**选择 CSV 文件上传预览**」：页面逐行展示解析后的时间 / 停留、演员处理方式（复用 / 新建 / 重名）、区域匹配情况与全部错误（未知 / 重名区域、时间或停留格式错误、文件内重复、现有口令冲突、必填缺失等）。重复按解析后的整数秒判定：同一演员、同一区域的 `90` 与 `01:30` 视为同一时刻，**文件内首次行**会标注「文件内首次出现（另有 N 数据行重复）」，其后的重复行标为错误；时间格式错误的行只保留格式错误，不参与重复判断。
4. **只要有错误行，「确认提交导入」按钮即为禁用状态**；按提示修改 CSV 后重新上传即可再次预览。
5. 全部行可导入后点击「**确认提交导入**」：若预览后底库被其他操作修改，会收到 409 提示「底库数据已变化，请重新预览」，点击提示中的「**重新预览**」按钮即可基于最新底库再次校验；
6. 提交成功后页面提示「**新增 N 位演员、M 条到位口令**」，演员 / 口令表格与校验结果自动刷新。整个提交为原子操作：写入过程中任何失败都会回滚，不会出现部分落库。

## 现场走位复盘操作说明

1. 启动服务后访问 **http://localhost:3000**（Docker Compose 一键启动，默认映射主机 `3000` 端口），在页面中部找到「**🎬 现场走位复盘**」卡片。
2. 准备 UTF-8 编码的 CSV 文件，表头固定为：

   ```csv
   演员姓名,角色,实际时刻,实际区域
   张三,饰 王子,00:20,舞台中央
   张三,饰 王子,01:30,侧台左
   ```

   - `演员姓名` + `角色`：必须能唯一对应一位**现有演员**（角色没有可留空，但需与底库一致）；
   - `实际时刻`：秒数（如 `90`）或 `mm:ss`（如 `01:30`）；
   - `实际区域`：必须与底库区域名**完全一致**；字段含逗号可用双引号包裹。
3. 点击「**选择现场记录 CSV 上传分析**」：未知演员 / 未知区域 / 歧义（同名同角色演员、重名区域）/ 时刻格式错误会**逐行列在「解析失败的数据行」表中，这些行不参与对齐**；修正后重新上传即可。
4. 结果区按演员展示**配对明细**（计划时刻 · 区域 ↔ CSV 行号 + 实际时刻 · 区域、时间偏差早到 / 晚到、区域偏差）与**漏执行口令 / 多余实际记录**清单，以及每位演员的时差合计、区域罚分、漏项 / 多项罚分与总成本；演员按总成本从高到低排列，优先暴露问题最大的走位。

## 观众视线遮挡检查规则

- **坐标系与单位**：平面坐标 x、y 与全部高度均为**整数厘米**；坐标取值 −1000000～1000000，高度 0～100000，遮挡物宽 / 深为 1～1000000 的整数。遮挡物为轴对齐矩形：`(x, y)` 为最小角，宽沿 x 轴、深沿 y 轴。
- **视线参数化**：对每条「观众点 → 舞台目标」线段取参数 `t ∈ [0,1]`：平面位置 `P(t) = 观众 + t·(目标 − 观众)`，视线高度 `h(t) = 眼高 + t·(目标高 − 眼高)`。
- **精确裁剪**：与每个矩形投影的相交参数区间用 slab 法（Liáng–Barsky 风格）计算，全程**分数运算 + BigInt 比较**，不做浮点近似、不只测矩形中心或采样点；**边界接触算相交**——区间退化为一点（贴边、角点相切）也计入相交区间。
- **遮挡判定**：相交区间内存在 `h(t) ≤ 遮挡物高度` 即被挡（**视线高度等于遮挡物高度算被挡**）；`h` 关于 `t` 线性，故只需精确检查区间两端点。
- **首挡物**：所有遮挡中的遮挡物里**进入参数最小**者（并列时取退出参数较小、再按 id 保证确定性）。
- **建议抬高**：求使视线在**全部相交遮挡物**（不只当前遮挡中的）的相交区间内**严格高于**其高度的最小整数目标高度 `H′`：对每个相交区间的每个端点 `t = p/q` 要求 `q·眼高 + p·(H′ − 眼高) > q·遮挡物高`，取严格大于全部阈值的最小整数（BigInt 向下取整 +1，不为负）；建议抬高量 = `max(0, H′ − 当前目标高)`。
- **无法抬高解决**：若某相交遮挡物的进入参数为 0（视线起点位于其投影内）且观众眼高不高于其高度，则该端点高度与目标高无关、恒被挡，标注「无法通过抬高目标解决」，`requiredTargetHeight / raiseBy` 返回 `null`。
- 本模块与走位校验互不影响，不参与基线对比与 Markdown 报告；数据保存在数据文件的 `audiencePoints` / `targets` / `obstacles` 字段中，旧数据文件没有这些字段时自动按空集合处理，完全兼容。

## 吊挂布景载荷核算规则

- **数据口径**：横坐标为 −1000000～1000000 的整数厘米；重量与额定载荷为 1～1000000 的整数千克；生效起止为不小于 0 的整数秒且开始严格小于结束。所有吊点位于同一横梁上，仅以横坐标区分位置。
- **重心约束**：吊挂件的重心横坐标必须位于左右吊点横坐标之间（**含端点**——重心正对某吊点时该点承担全部重量）；左吊点横坐标必须严格小于右吊点。
- **力矩平衡**：左点分担 = 重量 ×（右点横坐标 − 重心横坐标）÷（右点横坐标 − 左点横坐标），右点分担 = 重量 ×（重心横坐标 − 左点横坐标）÷（右点横坐标 − 左点横坐标）；两件分担之和恒等于重量。
- **有理数精确运算**：分担量、逐吊点累计载荷与额定载荷的比较全程使用分数（BigInt 分子 / 分母，自动约分），不做浮点近似。**超额 = 累计载荷严格大于额定载荷**；累计恰好等于额定载荷（如三件各分担 1/3 合成整数）不判超额，避免临界值舍入误判。响应与页面展示中的两位小数（`kg`）同样由精确分数经 BigInt 舍入得到（半数进位），多件分数分担叠加导致分子 / 分母达数百位时也不会因浮点转换失真为 `NaN`。
- **半开时段**：吊挂件按 `[起, 止)` 生效；同一秒**结束先于开始**——一件在 t 秒结束、另一件在 t 秒开始时，二者在 t 秒不叠加（与通道占用冲突的半开区间口径一致）。
- **峰值与超额区间**：逐吊点按事件时刻扫描分段恒定载荷，取最大值为**峰值载荷**（并记录首次出现时段）；载荷 > 额定载荷的连续时段输出为**超额区间**，**首尾相接的连续超额段合并为一条**，区间超额量 = 区间内峰值载荷 − 额定载荷（分数精确值）。
- **引用保护**：删除被吊挂件引用的吊点返回 409 并列出引用它的吊挂件；修改吊点横坐标后若某引用吊挂件的重心不再位于两吊点之间（或左右吊点横坐标关系被破坏）返回 400，本次修改不写入。
- 本模块与走位校验互不影响，不参与基线对比与 Markdown 报告；数据保存在数据文件的 `rigPoints` / `rigItems` 字段中，旧数据文件没有这些字段时自动按空集合处理（引用缺失吊点的吊挂件会被清理），完全兼容。

1. 启动服务后访问 **http://localhost:3000**（Docker Compose 一键启动，默认映射主机 `3000` 端口），在「跨演员口令依赖」卡片下方找到「**👔 演员换装核查**」卡片。

5. 登记 / 删除任务、编辑区域 / 连接 / 演员 / 口令、切换校验模式后，结果都会**即时重算**；点击每行「删除」可移除一项任务。

## 演员换装核查规则

- **任务定义**：一项换装任务绑定同一演员按时间排序**相邻**的两条到位口令（一个区段），登记**换装区域**与**所需整数秒数**（0～3600）；**每个区段最多一项**，重复登记返回 409，口令不属于同一演员、不相邻或区域不存在均返回 400。
- **表单选择保留**：页面重绘（切换校验模式、刷新结果、编辑其他数据）时，换装表单按两条口令 ID 保留仍相邻且未登记的区段选择，并保留换装区域与秒数输入；区段已被登记或因口令 / 区域变化失效时，**清空区段选择并提示重新选择**（不默认选中其他区段）；提交前按当前可登记区段再次核对，失效即阻止提交并保留其余输入，服务端的相邻性与重复登记校验为最终约束。
- **实际出发时刻**：取该区段在**当前校验模式**下推演得到的实际出发时刻——区段独立模式为起点口令计划时刻；连续口令延误传导模式为 `max(计划时刻, 实际到达) + 停留时长`（含继承延误）。即使原区段不可达，只要存在出发时刻，换装核查仍正常评估。
- **两段推演**：段一自实际出发时刻计算「起点口令区域 → 换装区域」的最早到达（**到达换装区时刻**）；**换装完成时刻 = 到达换装区时刻 + 所需秒数**；段二自换装完成时刻计算「换装区域 → 终点口令区域」的最早到达（**最终到达时刻**）。两段均复用时间依赖 Dijkstra，**通道封闭时段造成的等待或绕行自然计入**，而不是把各边静态最短耗时直接相加（第二段的通行环境取决于第一段的实际完成时刻）。
- **状态判定**：最终到达 ≤ 下一口令计划时刻为 ✅ **准时**（余量 = 下一口令时刻 − 最终到达）；否则 ❌ **迟到**（显示缺口秒数）；任一段在连接图上不连通为 ⛔ **不可达**（封闭时段只会造成等待或绕行，不会造成不可达）；关联口令 / 区域缺失或两条口令不再相邻为 ❓ **无法评估**（不猜测时刻）。
- **仅评估不改写**：换装核查是对该区段的独立评估，**不改变任何口令的出发 / 到达时刻**，不影响校验结果、通道占用冲突、基线对比与依赖判定，也不参与 Markdown 报告；模式切换后按新模式的事实重新评估。
- **级联清理**：删除口令（含删除演员 / 区域连带删除口令）时自动删除引用该口令的换装任务；删除区域时同时删除以该区域为换装区域的任务。数据保存在数据文件的 `costumeChanges` 字段中，旧数据文件没有该字段时自动按空集合处理，完全兼容。

2. 在「校验结果」卡片顶部选择校验模式（快照按**当前模式**的实际路线还原位置）。
3. 在「🚨 应急疏散快照」卡片输入**事件时刻**（支持 `90` 秒或 `01:30` 分:秒两种格式），并勾选**一个或多个出口区域**，点击「**生成疏散快照**」。
4. 结果区按**最晚撤离优先**列出每位演员：事件时刻位置（区域等待 / 停留 / 通道行进中及剩余路程）、出口、到达时刻、耗时与疏散路线；**无法疏散**（位置已知但无任何出口可达）排最前，**位置未知**（不可达链或时间轴未开始，不猜测）单独列于文末。
5. 快照生成后：编辑区域 / 连接 / 演员 / 口令或切换校验模式，快照会按最新数据与当前模式**即时重算**；点击「清除快照」可收起结果并恢复报告为不含快照的版本。
6. 快照生成期间点击「📄 导出校验报告」，下载的 Markdown 会在文末追加**同一快照**（事件时刻、出口、最晚撤离时刻、快照表与位置未知名单）。

## 通道封闭时段规则

- 每条连接可维护 **0 至多段**封闭时段，每段为起止秒数区间 `[开始, 结束)`（**含开始、不含结束**），开始必须严格小于结束，均为不小于 0 的整数秒。
- 演员在时刻 `t` 进入一条通行耗时为 `w` 的连接时，占用区间为 `[t, t+w]`；若该区间与任一段封闭区间**重叠**（`t < 结束` 且 `t+w > 开始`），则此时刻不可进入。
- 冲突时演员在该连接**起点所在的区域内等待**，直至封闭结束（最早可进入时刻 = 封闭结束时刻；多段封闭会依次向后滚动计算）。
- 校验算法会比较「等待」与「绕行其他路径」两种方案，取**最早到达时刻**的路线作为实际路线；等待位置与时长会在结果区和报告中展示。
- 封闭时段为有限区间，因此只会推迟到达、不会影响图连通性；「不可达」仍仅表示区域间没有任何连接路径。
- 旧数据文件中没有封闭时段字段的连接按「无封闭」处理，完全兼容。

## 通道占用冲突规则

- 在两种走位模式（区段独立 / 连续口令延误传导）各自算出逐边路线**之后**，将所有演员对每条**无向连接**的占用按半开区间 **`[进入, 离开)`** 汇总：进入时刻 = 该边实际出发时刻，离开时刻 = 实际到达时刻。
- 每条连接有**容量**（同一时刻允许并发占用的人数），默认为 **1**，可在连接编辑中设为 **1～10** 的整数；旧数据文件中没有容量字段的连接按 1 处理。
- 任一时刻并发占用人数（按演员去重）**超过容量**即生成冲突事件；超载状态先消失再出现的区间会被切开，**首尾恰好相接的连续超载区间合并为一条**。冲突事件列出：所在通道、容量、起止时刻与持续秒数、**峰值人数**，以及每位参与演员的**方向、进入/离开时刻、关联区段**。
- **首尾恰好相接不算重叠**：一方离开时刻恰等于另一方进入时刻时，不构成并发（半开区间）。
- **等待时间不占用通道**：因封闭时段在前一区域等待的时段不计入任何连接的占用。
- 结果区顶部给出跨演员的冲突汇总与明细卡片；涉及冲突的区段在其路线旁标记关联冲突（通道、时刻、峰值/容量）。
- Markdown 报告在汇总表中新增「🚶 通道占用冲突」计数，并增加「通道占用冲突汇总」一节（汇总表 + 每条冲突的演员 / 方向 / 起止 / 关联区段明细）；各区段表与路线明细中标注关联冲突。
- 注意：冲突是对**已推演路线**的事后校验，不会改变演员的出发 / 到达时刻；两种模式算出的路线不同，冲突结果也随之不同。

## 连续口令延误传导规则

- 每条口令可维护 **0～600 秒**的停留时长（整数秒，缺省 0；旧数据文件中没有该字段的口令按 0 处理，完全兼容）。
- 对每位演员按口令时间升序**连续推演**：**首条口令视为准时到位**（实际到达 = 计划时刻）。
- 从某条口令前往下一条时，**实际出发时刻 = max（该条计划时刻，实际到达该条的时刻） + 该条停留时长**；随后复用封闭等待 / 绕行算法计算下一条口令的实际到达。
- 某段迟到会**传导**给后续区段（继承延误逐段累积）；若后续口令间隔充足，到达仍不晚于计划时刻，则**延误被吸收**、恢复准时，不再向后传导。
- 结果区逐段展示：计划出发（计划时刻 + 停留）、实际出发、实际到达、继承延误（到达本段起点时已晚的秒数）与最终迟到（到达终点口令时晚于计划的秒数）。
- 不可达区段无法计算实际到达，其后区段自下一口令的**计划时刻**重新起算（传导链中断处会在报告明细中注明）。
- 「区段独立校验」模式不使用停留时长，也不做延误传导，行为与旧版一致。

## 应急疏散快照规则

- **位置还原**：以当前校验模式（区段独立 / 连续口令延误传导）已推演的逐边实际路线为唯一依据，将每位演员的走位展开为覆盖「首条口令时刻 → 之后」的时间轴，定位事件时刻所在区间：
  - 🚶 **通道行进中**：事件时刻落在某条连接的占用区间 `[进入, 离开)` 内；
  - ⏱ **区域等待**：在区域内等待封闭时段结束，或早到后等待下一口令计划时刻；
  - 🧍 **停留**：口令的计划停留时长内，或全部口令完成后停留在最终区域。
- **位于通道者**：先按原方向走完剩余路程（抵达时刻 = 该边实际到达时刻），再从到达区域计算疏散路线；区段独立模式下若后段口令按计划时刻重新起算导致位置窗口被截断，剩余路程仍以该边**真实抵达时刻**为准。
- **位于区域者**：从所在区域、事件时刻直接计算疏散路线；已位于出口区域者到达时刻即事件时刻、耗时 0。
- **疏散路线**：复用时间依赖 Dijkstra，在全部所选出口中取**到达时刻最早**者；事件时刻之后的封闭时段仍会造成等待或绕行（与走位校验同一套规则）。
- **位置未知**：事件时刻处于不可达区段（连接图不连通）期间、早于首条口令时刻、或演员没有口令时，单独标为位置未知，**不猜测**其位置；连续口令延误传导模式下，不可达区段自下一口令计划时刻起按该模式的重算规则恢复可知。
- **无法疏散**：位置已知但没有任何出口可达（如处于无连接的孤立区域），视为最晚撤离，排在结果最前。
- **排序**：结果按最晚撤离优先（无法疏散 → 到达时刻降序），位置未知者不参与排序、单独列出。
- 快照不修改任何走位数据，也不参与通道占用冲突与基线对比的计算；报告中的快照与页面为同一次计算结果。

## 跨演员口令依赖规则

- 依赖是两条口令之间的**有向约束**：`前置口令 --至少等待 N 秒--> 后置口令`，两条口令**可属于不同演员**（也可以约束同一演员的两条口令）；等待秒数为 **0～3600 的整数**。
- **完成时刻**（前置）：前置口令在**当前校验模式**下的**实际到达时刻 + 该口令的停留时长**（两种模式均使用口令自身的停留时长字段；停留期间演员仍在该口令区域）。
- **实际出发时刻**（后置）：前往后置口令的那个区段（同一演员按时间排序的上一条口令 → 后置口令）在当前模式下推演得到的**实际出发时刻**，其中已包含封闭时段等待、绕行与延误传导的影响。
- 判定：后置实际出发 ≥ 前置完成 + 等待 N 秒即 **✅ 满足**，相差秒数为余量；否则 **❌ 违约**，相差秒数为负的缺口（报告与页面显示「缺 X 秒」）。
- **❓ 无法判定**：前置 / 后置口令缺失或未参与推演、前往任一端口令的区段**不可达**（实际到达未知）、或后置口令是该演员的**首条口令**（没有前往该口令的区段，无实际出发时刻）时，不猜测时刻、单独标为无法判定并注明原因。
- 依赖**不改变走位推演**（不会推迟任何出发 / 到达时刻），仅在两种模式各自算出实际路线之后做事后校验，与通道占用冲突同级；模式切换后同一张依赖图会按新模式的时刻事实重新判定。
- **环检测**：新增依赖保存前对整张依赖图做 DFS 环检测，成环（含自环）时整次请求 400 失败、**不写入任何数据**，错误信息包含可直接阅读的闭环口令链（如 `李四 00:20 舞台中央 → 张三 00:35 二层平台 → 李四 00:20 舞台中央`）；需删除环上某条已有依赖后才能添加新约束。
- **级联清理**：删除口令时自动删除引用该口令（任一端）的依赖；删除演员 / 区域连带删除口令时同样级联清理。

## 现场走位复盘规则

- **CSV 格式**：UTF-8 编码（可带 BOM），表头必须恰好包含 `演员姓名,角色,实际时刻,实际区域` 四列（允许不同列序，仅按表头名识别）；`实际时刻` 为秒数（`90`）或 `mm:ss`（`01:30`）；整行空白自动跳过。引号规则与导入完全一致（见上文「CSV 引号规则」）：引号只能出现在字段起始、引号内以 `""` 表示字面引号、闭合引号后只允许逗号 / 换行；未加引号字段中出现引号（如 `张"三"丰`）、闭合引号后夹带字符或引号未闭合均为**文件结构错误**，分析与报告下载统一返回 400、不产生任何对齐结果。
- **仅解析现有数据**：演员按「姓名 + 角色」、区域按名称在当前底库中精确查找；查无此人 / 此地（未知）或匹配到多个（歧义）均为行级错误，错误行**不参与对齐**，系统不会新建演员或区域。
- **排序口径**：每位演员的计划口令按「计划时刻升序，时刻相同按口令 ID 字典序」排列；实际记录按「实际时刻升序，时刻相同按 CSV 物理行号升序」排列。
- **保序一对一最优对齐**：在两侧排列上做序列对齐（Needleman–Wunsch 风格 DP），配对不得跨越先后顺序，且**每条计划口令与每条实际记录至多参与一次配对**。
- **成本函数**：一次配对成本 = `|实际时刻 − 计划时刻| +（实际区域 ≠ 计划区域 ? 300 : 0）`；一条计划口令没有对应实际记录（漏执行）计 **180**；一条实际记录没有对应计划口令（多余）计 **180**。
- **同成本决胜**：总成本相同时先取**配对数更多**的方案；配对数再相同则取**配对到的实际记录 CSV 行号序列字典序更小**的方案（逐行号比较，较短前缀序列优先），保证结果唯一且可复现。
- 因为一次「漏执行 + 多余」合计 360：当某对配对的成本（时差绝对值，区域不符时再加 300）超过 **360** 时，最优解会将两侧分别判为漏项与多项，而非强行配对。
- 复盘全程只读，不调用任何写库逻辑，也不影响校验结果、通道冲突、基线与依赖；报告由同一份 CSV 在服务端重新计算生成。

| POST | `/api/import/commit` | 提交导入：请求体 `{ csv, version }`；底库版本与 `version` 不一致返回 **409**（要求重新预览）；按原始 CSV 重新解析并**复用预览的同一判重口径**复核，存在**文件结构错误（含非法引号）**或错误行（含文件内重复 / 现有口令冲突）返回 400 且**整批拒绝、不写入任何演员或口令**；校验通过则一次性原子写入全部新演员与口令，返回 `{ createdActors, createdCues, version }`（201），合法文件实际新增数与预览数一致，任何写入失败均回滚、不部分落库 |
| POST | `/api/replay/analyze` | 现场走位复盘分析（**只读、不写库**）：请求体 `{ csv }`（表头 `演员姓名,角色,实际时刻,实际区域`）；返回 `rows`（逐行解析结果与 `issues`、`valid`、CSV 物理 `line` 行号）、`actors`（逐演员的 `pairs` 配对明细含时间 / 区域偏差与配对成本、`missed` 漏执行口令、`extra` 多余实际记录、`cost` 各项成本）、`summary`（总行数 / 有效行 / 错误行 / 配对 / 漏项 / 多项 / 区域不符 / 时差合计 / 总成本）与 `costRule`（300 / 180 口径）；CSV 结构错误（空、缺列、**非法引号——未加引号字段中出现引号、闭合引号后夹带字符、引号未闭合**、仅表头）返回 400 |
| POST | `/api/replay/report` | 下载本次复盘 Markdown（**只读、不写库**）：请求体 `{ csv }`，服务端按原始 CSV 重新计算后返回 `text/markdown; charset=utf-8` 附件（含汇总、CSV 逐行解析问题、每位演员配对 / 漏项 / 多项明细）；CSV 非法（含上述非法引号结构错误）时同样返回 400 |
| GET | `/api/sightlines` | 观众视线遮挡检查：对每位观众点 × 每个舞台目标精确裁剪视线段与各矩形投影的相交参数区间（边界接触算相交、视线高度等于遮挡物高度算被挡）。返回 `pairs`（逐对结果：`status` 为 `clear`/`blocked`、`firstObstacle`（最小进入参数的首挡物）、`intersections`（各遮挡物的进入 / 退出参数，含精确分数 `num/den` 与 6 位小数 `t`、是否遮挡）、`clearable`、`requiredTargetHeight`（严格越过全部相交遮挡物的最小整数目标高度，无法解决时为 `null`）与 `raiseBy`（建议抬高量））与 `summary`（观众点 / 目标 / 遮挡物 / 视线对 / 通视 / 被挡 / 无法抬高解决计数） |
| GET | `/api/rigging` | 吊挂布景载荷核算：逐吊挂件按力矩平衡分担（分数精确值），逐吊点按半开时段 `[起, 止)` 汇总载荷（同秒结束先于开始）。返回 `points`（按横坐标升序：`peak` 峰值载荷、`peakInterval` 峰值首次出现时段、`overloaded` 与 `intervals` 合并后的超额区间——含起止秒数、持续秒数、区间峰值 `peakLoad` 与超额量 `excess`，载荷均以 `{ num, den, kg }` 给出精确分子分母与 2 位小数值，`kg` 由分数经 BigInt 精确舍入、多件分担叠加成分数巨大时仍为有限数值）、`items`（逐件左右吊点分担明细）与 `summary`（吊点 / 吊挂件 / 超额吊点 / 超额区间计数） |
| POST / PUT / DELETE | `/api/areas`、`/api/edges`、`/api/actors`、`/api/cues`、`/api/audiencePoints`、`/api/targets`、`/api/obstacles`、`/api/rigPoints`、`/api/rigItems`（`/:id`） | 九类资源的增改删；删除被吊挂件引用的吊点返回 409，修改吊点横坐标破坏吊挂件重心约束返回 400。连接（`edges`）按**拟更新后的完整连接**判重：无向连接正、反方向视为同一对端点，创建时同对已存在返回 409；更新时与除自身外的现存连接同对返回 **409 且不写入**——冲突时被编辑连接（端点 / 耗时 / 容量 / 封闭时段）及其它数据的内存状态与数据文件均保持原样；合法更新一次落盘，走位校验按新连接重算 |

`edges` 的创建 / 更新请求体示例：

```json
{
  "a": "area-wing-r",
  "b": "area-center",
  "seconds": 4,
  "capacity": 1,
  "closures": [ { "start": 10, "end": 14 }, { "start": 30, "end": 36 } ]
}
```

`closures` 可省略（等价于无封闭）；每段需满足 `0 ≤ start < end` 且为整数秒，否则返回 400。

`capacity`（通道容量）可省略：创建时缺省为 `1`，更新时不传则保留原值；需为 `1～10` 的整数秒，否则返回 400。旧数据文件中没有该字段的连接按容量 1 处理，完全兼容。

更新连接端点（`PUT /api/edges/:id`）时，服务端按**拟更新后的完整连接**判重：无向连接正、反方向视为同一对端点，若与除自身之外的任一条现存连接同对，返回 409「两个区域之间已存在连接」，且**本次请求的全部字段（端点 / 耗时 / 容量 / 封闭时段）都不写入**，内存与数据文件保持冲突前原样；仅颠倒自身端点顺序（仍是同一对区域）不算重复。端点不变、只改耗时 / 容量 / 封闭时段为合法更新，保存后单次落盘并即时重算走位校验。

`cues` 的创建 / 更新请求体示例：

```json
{
  "actorId": "actor-zhang",
  "areaId": "area-center",
  "time": 20,
  "dwell": 8,
  "note": "上台亮相"
}
```

`dwell`（停留时长）可省略，缺省为 `0`；需为 `0～600` 的整数秒，否则返回 400。更新时不传 `dwell` 则保留原值。

观众视线遮挡检查三类资源的请求体示例（均为整数厘米）：

```json
// POST /api/audiencePoints
{ "name": "A 区 1 排 1 座", "x": 500, "y": -800, "eyeHeight": 120 }
// POST /api/targets
{ "name": "舞台中央表演点", "x": 1500, "y": 500, "targetHeight": 160 }
// POST /api/obstacles（x、y 为最小角，宽沿 x 轴、深沿 y 轴）
{ "name": "乐池护栏", "x": 0, "y": -300, "width": 3000, "depth": 100, "height": 110 }
```

坐标 x、y 需为 −1000000～1000000 的整数；眼高 / 目标高 / 遮挡物高为 0～100000 的整数；宽、深为 1～1000000 的整数，否则返回 400。

吊挂载荷核算两类资源的请求体示例：

```json
// POST /api/rigPoints
{ "name": "吊点 A", "x": 0, "ratedLoad": 500 }
// POST /api/rigItems（重心须位于左右吊点之间，左吊点横坐标须小于右吊点）
{ "name": "天幕景片", "weight": 240, "cogX": 200, "leftPointId": "rig-a", "rightPointId": "rig-b", "start": 0, "end": 90 }
```

吊点 / 重心横坐标为 −1000000～1000000 的整数厘米；重量 / 额定载荷为 1～1000000 的整数千克；生效起止为不小于 0 的整数秒且开始 < 结束，否则返回 400。

`dependencies` 的创建请求体示例：

```json
{
  "predecessorId": "cue-l2",
  "successorId": "cue-z3",
  "waitSeconds": 5
}
```

含义：`cue-l2`（前置口令）在当前模式下实际到达并完成停留后，至少再等 5 秒，`cue-z3`（后置口令）的实际出发时刻才允许到来；两条口令可属于不同演员。新增后服务端立即对整张依赖图做环检测，成环返回 400（含闭环口令链）且不写入；同方向重复返回 409。

`costume-changes` 的创建请求体示例：

```json
{
  "fromCueId": "cue-l2",
  "toCueId": "cue-l3",
  "areaId": "area-upstage",
  "seconds": 12
}
```

含义：同一演员（`cue-l2` 与 `cue-l3` 须属于同一演员且按时间排序相邻）在该区段需要到「舞台后区」换装 12 秒；核查时按当前模式取该区段实际出发时刻，先算「起点 → 换装区」最早到达，加 12 秒得换装完成时刻，再算「换装区 → 终点」最早到达，与 `cue-l3` 的计划时刻比较得出准时 / 迟到。每个区段最多一项，重复登记返回 409。

`/api/import/preview` 与 `/api/import/commit` 的请求体示例：

```json
{
  "csv": "姓名,角色,目标区域,时间,停留秒数,口令说明\n张三,饰 王子,舞台中央,01:30,8,上台\n赵六,饰 侍卫,侧台右,45,,候场",
  "version": "a852dd9e962fb02552ff03688ea40034faa2133382639a7dde4cb5e45551fa4"
}
```

`csv` 为 CSV 文件原文（`version` 仅提交时需要，取自预览响应）。行级错误码（`rows[].issues[].code`）：`name-required` / `name-length` / `role-length`（姓名角色缺失或超长）、`area-unknown`（未知区域）、`area-ambiguous`（重名区域）、`actor-ambiguous`（同名同角色演员不唯一）、`time-required` / `time-format`（时间缺失或格式错误）、`dwell-format`（停留秒数非 0～600 整数）、`note-length`（说明超长）、`duplicate`（文件内重复）、`conflict`（与现有口令冲突）。
